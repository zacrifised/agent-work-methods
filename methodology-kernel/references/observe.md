# 前置与观测类原则（P0–P5）

统一格式：**一句话 / 判别问句 / 已知反例 / 谁在用**。
判别问句是给"这条到底适不适用"用的，不是复述原则。

## P0 标准先行

**一句话**：日志能证明"**发生了什么**"，但**标准**决定"**算不算问题**"。
先立标准（不变量），再判断现象是否违反它——**顺序不能反**。

**判别问句**：在判断之前，我能写出"什么是对的"吗（不变量模板）？
写不出 → 降级为"现象调查"或"上下文补齐"，**不进入责任端定性**。

**已知反例**：

1. **默认标准未必适用**：「零缺陷」「验证越充分越好」不是普适目标，
   质量目标应从**业务目标倒推**。
2. **代码不是需求真源**：期望不能只由代码反推——代码描述"是什么"，
   不能定义"应该是什么"。
3. **多来源冲突时不默默平均**：写明冲突、选一个、说明理由。
4. 分开记 **现象存在性置信度** 与 **根因置信度**：现象确凿不代表原因确凿。

**谁在用**：`排查方法论 skill/references/evidence-standards.md`、
`qa-evidence-and-artifacts`（判定"这是不是问题"）。

## P1 方向不对称

**一句话**：正向信号（200 / 握手成功 / 自测通过 / 没报错 / 跑通了）只能推出
"该节点不是断点"，用于**排除**；负向信号（500 / 404 / 超时 / RST / 崩溃）才能**定位**。
只有端到端能宣布"通"。

**判别问句**：这条观测**变好**时我能排除什么？**变差**时我能定位到什么？
两个都答不出 → 这条观测零信息量，别放进报告。

**已知反例（四种，都很常见）**：

1. **节点异常 ≠ 阻塞用户**，中间隔着"是否在关键路径"。
   某域名根路径返回 404/403 且根路径本就无路由 → 不构成阻塞。
   两级推理不能并成一级。
2. **只看状态码等于没测**：要校验返回内容是不是用户要的东西，
   有没有被重定向到登录页（未登录测出的结论对已登录场景不可外推）。
3. **补偿机制会抹平指标**：网卡降速被重传补偿，吞吐看起来正常。
4. **自愈系统会自己恢复**：等你观测时指标已回到正常，看不到故障窗口。

**谁在用**：`变更验证`（Q1/Q2 判据）、
`qa-evidence-and-artifacts`（必现走 E2E 链）、
`test-strategy-design`（L0 E2E 通过不证明用户可用——同一条原则的另一套措辞）。

## P2 代理 ≠ 目标

**一句话**：测到的量如果只是真机制的**间接指标**，写清它覆盖不到的边界，
不要把代理当成机制本身。

**判别问句**：如果这个指标正常，机制**仍然可能坏**吗？
答"可能" → 它是代理，必须写边界。

**已知反例**：日志有没有、HTTP 状态码、重跑通过率、平均帧率（体感是低分位帧）。
极端例子：OCR 引擎输出的**置信度**对识别错误**零判别力**（Pearson r = 0.001），
看起来像强信号，实际是完全无用的代理。

**谁在用**：`排查方法论 skill` 四条翻车规则之四、
`变更验证/references/traps.md`。

## P3 先读后断

**一句话**：能读到的东西不要推断；读不到才推断，并且标注出来。

**判别问句**：这个值是**读到的**还是**猜的**？
设备状态 / settings / 系统版本 / 日志 / 配置项，一律先读。

**已知反例**：这条本身没有不适用情形。代价是慢——时间紧时至少标注
「未读，推断」，而不是用推断冒充读数。

**谁在用**：`evidence-discipline` F4。

## P4 量纲要校验

**一句话**：时间看**时区与零点**、容量看**单位与分母**、速率看**时间窗**、
日志看**滚动规则**。先校验再运算。

**判别问句**：这个数的零点在哪、单位是什么、时区由谁记？

**已知反例（本机踩过）**：

- 日志时间戳是 UTC 不是 UTC+8 → 整条时间线错 8 小时，因果关系全反
- 只读到 `max_soc=100` 没读 `min_soc=2` → 误判用户没做过满循环
- 用平均值回应体感峰值 → 制造"数据与你不符"的假矛盾

**谁在用**：`evidence-discipline` F5。

## P5 检测器先自检

**一句话**：用一个检测手段下结论之前，先**注入一个已知故障**，确认它会报警。
不会报警的检测器，全绿毫无意义。

**判别问句**：如果我故意把它弄坏，它会响吗？

**已知反例**：

1. **用排除清单而非区段判定的检测器会持续输出噪声**
   （乱码扫描用逐字白名单 → 反复误报正常排版字符）。
2. **指示器被自愈或补偿抹平**：故障真实发生，检测器看不见。
3. **只查状态码 200 不看响应内容**：永远绿。

**谁在用**：`变更验证/references/detector-check.md`。
本内核自身的检测器（`变更验证/scripts/check_skill.py`）也按这条自检，
注入故障记录写在它的源码 docstring 里。
