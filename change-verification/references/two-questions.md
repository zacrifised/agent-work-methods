# Q1 / Q2 判据与基线

## Q1：改动是否确实有效

写法：`改前 A → 改后 B，预期方向是 <...>`，附原始输出。

| 要素 | 要求 |
| --- | --- |
| 正向观测 | 预期效果出现的具体值 / 行为 / 产物字节数 |
| 原始输出 | 贴命令返回，不转述 |
| 反向对照 | 改前状态 A；注入已知故障只用于验检测器，不用于证明改动有效 |

只写「没报错」不算 Q1 通过。

## Q2：是否破坏原有

写法：与基线逐项比对，出差异清单；无差异写「与基线一致（列出比对项）」。

## 基线三形态

| 形态 | 内容 | 成本 |
| --- | --- | --- |
| 命令输出快照 | 改前同一命令的 stdout / exit code | 低 |
| 文件哈希 / 内容读回 | 受影响文件的哈希或全文 | 中 |
| 行为序列 | 关键路径的操作序列与返回值 | 高 |

第一次跑就存基线。基线路径写进验证报告。

## 无基线时

写「未覆盖」并列出未覆盖的面，不写「没发现问题」。
补基线后重跑 Q2，覆盖状态才能改。

## 观测能力算既有功能

若改动触及日志 / 指标 / 告警 / 自动化，把这些通道本身列入 Q2 比对项；
通道被改哑时，功能仍在跑也不算 Q2 通过。
