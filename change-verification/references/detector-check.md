# 检测器自检

## 做法

```
0. 选定本次改动的真实验证命令，记录命令原文（不由自检脚本代跑）
1. 故意改坏一处（本次改动点，或检测器本该抓到的东西）
2. 跑第 0 步记下的同一套验证
3. 期望：验证失败 / 报警
4. 判读：
   报警 → 检测器有效，此前的「全绿」才可信
   没报警 → 检测器无效，前面所有「通过」作废，先修检测器
5. 还原被改坏处，写还原确认
```

## 必须做的情形

| 情形 | 是否必须 |
| --- | --- |
| 依赖自动化脚本 / CI 做验证 | 必须 |
| 验证只看退出码或状态码 | 必须 |
| 改动触及检测规则本身 | 必须 |
| 单点手工改动、可立即回滚 | 必须（无例外；范围可缩小，注入动作不可跳过） |

## 故障选型

| 类型 | 注入什么 | 期望 |
| --- | --- | --- |
| 被检物坏 | 把改动点改回坏状态 | 对应检查项翻红 |
| 检测器坏 | 把检测词表 / 阈值改空 | 自检自身翻红 |
| 通道坏 | 把退出码短路成恒 0 | 原始观测量仍显示不通过 |
| 运行条件兜底 | 加外部环境变量掩盖 | 实验须移除兜底再跑 |

## 判定口径

- 判定按原始观测量（计数 / returncode / 差异列表），不按检测器的结论通道。
- `returncode` 与期望退出码不符时，单独记「退出码通道异常」，不改变按证据得出的结论。
- 检测器不宣布放行；自检结果只作证据。
