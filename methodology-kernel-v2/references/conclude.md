# 结论类原则（P8–P13）

## P8 证据先于结论

**一句话**：先有可被检视的证据，再有结论；没有证据时不填结论，填**证据缺口**。

**判别问句**：这条结论背后那条可检视的证据是哪一条？指不出来就降级。

**已知反例**：「没找到反证」「跑通了 / 没报错」都不是正向证据——按 P1 那只能排除。

**谁在用**：`排查方法论 skill` 总则一、`evidence-discipline` F1。

## P9 经得起 challenge

**一句话**：写下一条结论前自问——如果有人拿**同样的证据**来质疑它，我拿什么顶回去？
顶不住就不叫结论，叫**领先方向**。

**判别问句**：证据来源、适用范围、反例、验证成本，四样我写得出来吗？

**边界（容易做错的地方）**：

- **禁止空泛免责语**——「不排除存在其他可能」这类话不提供任何可执行信息，
  写了等于没写，反而稀释结论。
- **但必须写可执行的边界**：适用范围（在哪些版本 / 路径 / 条件下验证过）
  + 已经做过的反例搜索（做过什么、没找到什么）。
- 这两句不矛盾：前者是措辞，后者是内容。**用内容替代措辞**。

**谁在用**：`排查方法论 skill` 总则二、`evidence-discipline` F6。

## P10 排他的三边界（完整版）

**一句话**：能交付的结论 = 有决定性证据 + 对候选集排他 + 列得出被排除项。

1. **决定性证据**：观测到"它成立才该看到、它不成立就不该看到"的东西。
   决定性 = 有**区分力**（能把 H 与其余候选分开），不是"没找到反证"。
2. **排他 = 排除了其余候选**，不是排除了全部可能性。
   仍可能出现"连胜出的这个候选也不是 root cause"——那意味着**候选集本身不全**（少见）。
   察觉手段：调查中靠**卡死信号**（所有候选都解释不了现象 / 连续实验 `unchanged` /
   想不出新判别实验）；交付后靠**按结论修复或规避了但现象仍在**这条反例。
   命中后唯一正确动作是重开第 1 步重列假设，不是在同一空间里加实验。
3. **排不掉 = 没有确定结论**。降级为**领先方向 + 下一个判别实验 + 写明未排除项**。
   这是兜底路径，**不是失败**。不要为了闭合结论牺牲排他性——那是最贵的一种省事。
4. **root cause 可能不唯一** ⇒ 结论可以是多个候选**并列**。
   前提是各自都**独立**拿到正向证据；凑不出证据的并列叫"领先方向"，不叫结论。
5. **并列只适用于独立候选**——见 P11。

**一条容易被忽略的推论**：区分力只在**候选集内部**有效。候选集错时，
区分力越强反而错得越自信。而**候选集完备性在调查中没有内部判据**——
它只由三样东西提供：外部先验（两轮检索）、案例库、事后反例。
所以外部先验不是"ROI 高的可选项"，它是**候选集完备性的唯一来源**。

**谁在用**：`排查方法论 skill` 总则。

## P11 先判候选关系，再定结论形态

**一句话**：候选之间不是一律独立的。先判关系类型，它决定结论该长什么样，
也决定**该用哪种 RCA 方法**。

| 关系 | 判据（A 成立时，B？） | 结论形态 |
|---|---|---|
| **互斥** | B 必不成立 | 单选，二选一 |
| **独立并存** | B 不受影响 | 可多因并列；**不归一化到 100%** |
| **因果链** | B 必然 / 高概率成立 | **一个 root cause + N 个下游表现，不并列** |
| **包含** | B 是 A 的子情形 | 归到更具体的那一层 |
| **共因** | A、B 同被 C 导致 | 结论是 **C**，A / B 是并列表现 |

**判别问句**：**如果 A 成立，B 是否必然或高概率也成立？**
是 → 因果链或包含，**不是独立**。

**关系类型 → 该用哪种 RCA 方法**（业界按"问题形状"选方法的通行分类）：

| 问题形状 | 该用的方法 | 它防的是什么 |
|---|---|---|
| 单一线性因果链 | 5 Whys | 停在最像的那个近因，没挖到系统性条件 |
| 原因散在几个独立类别 | Fishbone / Ishikawa（6M 或其软件变体） | 锚定在人因，从不系统查其他类 |
| 只在多条件 / 防线同时失效时才发生 | 故障树 FTA（AND / OR 门，IEC 61025） | 修了一条支路，其他通路仍然活着 → **复发** |

**反例（代价最大的一种错）**：把因果链上的成员当成多个独立 root cause。
例：连接池配置过小 → 连接耗尽 → 接口超时 → 前端白屏。
若把「配置错 / 接口超时 / 前端渲染失败」列为三个独立候选，
按 P10 第 4 条会输出**三个并列 root cause**——实际是一个原因 + 两个下游表现。
后果是开发同时改三处、修复效果无法归因。

**关系判不出来时怎么办**（默认偏召回）：
列出所有 contributing factor，但**必须带结构标签**，不许给一个扁平的多因清单：

| 标签 | 含义 | 是否要单独修 |
|---|---|---|
| `root cause` | 链上**最深的可行动者** | 要，**且只有一个** |
| `传导路径` | 链上中间环节 | **明确标注"不需单独修"** |
| `独立 contributing factor` | 与 root cause 无关的第二原因 | 要，独立动作 |
| `防线失效` | 本该拦住但没拦住（检测失效 / 响应失效） | 要，独立动作 |

偏召回的判别依据：

- 故障树的约定：**回顾性分析用 AND 门**（描述已发生的事故 → 多条件并存）；
  拿不准时用 OR 门（假设最坏情况 = 更多独立通路）。**两条都指向"宁可多列"**。
- Google SRE 明确说 RCA 找的是 **contributing factors，复数**，不是单个 root cause；
  复盘模板分列 proximate cause / contributing factors / detection failure /
  response failure，**各自配独立的修复动作**。
- 代价不对称：**误报多因 = 多做一处修复（浪费，但问题解决了）；
  漏报多因 = 修了 A，B 仍触发（复发）。复发比浪费贵。**

**"稀释修复责任"不是反对多因的理由**：业界的解法是给每个 factor 配
独立的 action + owner + due date，而不是砍掉 factor。
每个 factor 拿不出独立动作时，它就不是 contributing factor，退回"线索"。

## P12 机制声明门

**一句话**：宣称"机制是 X"之前，先做**反例搜索**——有没有一个已知事实
会被这个机制排除掉？有，机制就是错的。

**判别问句**：有没有一条我已观察到的事实，在这个机制下**不该出现**？

**已知反例**：表象 ≠ 根因。光之子白屏案——表象指向渲染，
根因是 `ntdll!RtlEnterCriticalSection`，反例搜索能提前拦掉错误机制。

**谁在用**：`排查方法论 skill` 四条翻车规则之三。

## P13 一致不产生信息

**一句话**：只有**分歧**产生信息。两个来源一致不能当作支持证据——
禁止"互相印证 / 佐证"式论证。

**判别问句**：双方一致的部分，有没有可能源于**同一个错误前提**？
（共享先验的两个来源，一致毫无信息量。）

**边界**：一致不是完全无用，它能提供覆盖上的安慰；
但**不能被写进论证**。能写进论证的只有分歧及其裁定结果。

**谁在用**：`独立复核`（整个 skill 建立在这条上）、
`evidence-discipline` F2。

### P13 的前置检查：先问两条读数是不是同一条测量链（观察，n=1，待晋升）

**一句话**：在说"两者一致"之前，先确认它们是**两条独立的测量链**，
还是**同一条链的两种表示**。若同源，连"一致"都谈不上——那只验证了你的算法，没验证测量。

**判别问句**：这两个读数，是同一个传感器的**原始值与它的积分/均值**，
还是两套各自独立采样的硬件/通道？

**已知反例（导航窗口案例）**：
用库仑计 `remaining_cap` 差值算出 533.6 mA，又用 `ibat` 采样积分算出 531.1 mA，
差 0.5%。我差点把这条写成"两条独立口径交叉验证通过"。
**错**——`remaining_cap` 就是电量计对 `ibat` 的积分，两者同一条链。
0.5% 的吻合只证明我的黎曼和算对了，**整段分析实质上只有一条测量通道**。
（这次唯一接近独立的旁证是 `ui_soc` 口径 11.7 %/h vs 库仑计 11.8 %/h，
但 ui_soc 是整数量化值，±0.5% 在 91 mAh 上就是 ±24% 的不确定度，只能算弱旁证。）

**反过来的用法**：**分歧仍然产生信息**，前提是通道独立。
反例（同一台机器）：`socd` 恒为 40 ℃，而同期 `cpuss-0` 58.6–63.3 ℃、`gpuss-0` 55.9–59.0 ℃——
物理上不可能，据此判定 `socd` 上报通道不可信。

**不适用**：两条读数来自不同硬件传感器/不同进程/不同采样率时，一致性仍按 P13 处理（不写进论证），
但**分歧**是高价值信号，可以直接用来废掉其中一个通道。

**待晋升条件**：再攒 1 个独立场景（不同设备或不同传感器族）即可升为规则。
