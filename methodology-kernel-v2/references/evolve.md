# 进化类原则（P14–P15）+ 五道闸门

## P14 n=1 不泛化

**一句话**：单次观察只记为「观察」，不晋升为「规则」。

**判别问句**：这条经验是来自**一个场景**还是**两个以上独立场景**？
同一场景重复出现多次仍然只算一次。

**已知反例**：一次 bug 修好了 → 写成"以后遇到 X 就这么做"。
最危险的固化是**把噪声当信号**：单次成功可能是运气、可能是耦合了当时环境。

**关联**：`独立复核/references/pitfalls.md` 里的
「n=1 时写 X/Y，不要写百分比」是同一条原则在表达层面的版本。

## P15 显式撤回

**一句话**：被证伪的说法要**写明作废**，不静默修改；**记录保留，不删除**。

**判别问句**：我这次改的是"补充"还是"推翻"？是推翻 → 进撤回台账。

撤回记录必须保留：它记录判别过程，价值高于规则本身。

**区分两种撤回**：

| 类型 | 含义 | 处理 |
|---|---|---|
| **被证伪** | 结论错了 | 明确写"此说法作废"+ 判别实验 |
| **被精化 / 被取代** | 不算错，但不完整或被更好的表述取代 | 写"已由 XX 取代"，保留原文指针 |

**谁在用**：`evidence-discipline` F3。集中台账：`references/retracted.md`。

## 五道闸门（规则变更的准入条件）

**任一条不满足就不许落地。** 这不是流程洁癖——
没有闸门的自进化等于把噪声自动固化成规则。

### 闸门 1：晋升门槛

≥2 次**独立场景**命中，才从「观察」升为「规则」。
同一场景重复出现 5 次仍然只算 1 次。

### 闸门 2：反例栏

没写「不适用于」的规则不许晋级。
一条没有边界的规则，迟早会被应用到它不适用的场景，然后被打回——
那时已经产生了错误结论。

### 闸门 3：衰减与复审

长期未命中、或被反例命中 → **降级或撤回**，但**记录保留**（P15）。
规则只增不减的系统必然膨胀到没人读。

### 闸门 4：硬核保护

总则类（P8–P11）**只能人工改**。自进化机制只能动操作层规则。
总则类（P8–P11）的口径形态不允许自动漂移。

### 闸门 5：改完必跑检测器

引用完整性 + 乱码扫描 + **内容保全回归**（有基线才判得动回归）。
对应 `变更验证` 的 Q1/Q2。

### 剂量控制

单次会话**最多沉淀 3 条**新规则。膨胀到没人读，比少记几条更糟。

## 进化台账格式

各 skill 首次进化时自建 `evolution.md`。
字段按闸门设计，缺一项就不许晋级：

```
观察（场景 / 单次） → 命中次数（独立场景计数） → 候选规则表述
→ 反例栏（不适用于） → 状态（观察 / 规则 / 已降级 / 已撤回）
→ 判别实验 → 复审日期
```

## 自进化不只进内容，也包括撤回

已发生的撤回集中在 `references/retracted.md`。
一个只会加规则、不会撤回规则的系统，不是自进化，是**自膨胀**。
