# 结案类原则（P16–P18）

> 这补上了原有方法论最大的缺口：**只教了怎么往下追，没教什么时候停**。
> 本次用满「单次会话最多 3 条新规则」的额度，其余经验只记案例，不晋升规则。
> 统一格式：一句话 / 判别问句 / 已知反例 / 不适用于 / 谁在用。

## P16 证明标准按决策代价分级

**一句话**：证据强度（【已证实】/【推断】/【未证实】）描述的是**证据有多硬**；
「够不够收口」是另一个维度，由**决策代价**决定。
低代价、可逆、用户无感知的问题，可以用**高度盖然性**（优势证据：待证事实成立的可能性
明显大于不成立）给出合理推定并结案，不必等到排他或判别实验。

**判别问句**：这个结论错了，最坏后果是什么？可逆吗？用户什么都不做，会有感知吗？

| 决策代价 | 该用的证明标准 | 可交付形态 |
|---|---|---|
| 高 / 不可逆（数据丢失、安全、对外发布、用户明确要根因） | 决定性证据 + 对候选集排他（P10） | 【已证实】 |
| 中 / 可逆 | 判别实验 + 反例搜索（P12） | 【推断】+ 证伪条件 |
| 低 / 无感知 | 高度盖然性（优势证据） | 合理推定 + 明确写「到此结案」 |

**结案触发条件**（命中 ≥1 条就应提出结案并等用户决定；四条同时满足就直接停）：

1. **无用户可感知影响** —— 不看监控就没有感知。是观测行为本身制造了「问题感」。
2. **达到可归因边界** —— 根因在第三方闭源组件内部，本机证据源不覆盖；再投入只能堆推断。
3. **已有合理推定** —— 机制自洽、有独立数据支撑、无明显反例；继续追的边际收益趋零。
4. **旧现象无法复现且形态已变** —— 见 P17。

**零号信号（优先于上面四条）**：用户**明确声明**
「这不是必须解决的问题 / 纯粹只是好奇 / 我更看重别的」时，直接结案，
不必再自己评估影响面与可归因边界 —— 决策代价由用户本人给了，不用我代判。
判别问句：他是在**问答案**，还是在**用这个问题看过程**？后者就不是一道待解题。

> case **之后**（19:02 写入，而用户 18:47 已点破、18:48 才第一次加载 `conduct.md`）。
> **不能用事后写下的规则去给事前的行为定「违规」** —— 那是 F9 时序错配。
> 该 case 只能记为「漏判的现象」，不能记为「读了没遵守」的违规样本。

**结案 ≠ 停止投入**：问题结案后，正确动作是把预算从「追根因」转到「提炼可迁移经验」，
而不是草草收场、也不是硬找下一个实验。本会话用户原话：
「都不是什么必须解决的问题……但我看重的是，你和我在这些对话/澄清/沟通中，是否能有所成长。」
→ 交付物从「答案」变成「沉淀」。用户叫停的场合同样适用。

**已知反例**：

- 本会话：火绒服务线从 00:26 连追到 00:58，共 5 轮（7031 全文、7045 全历史、
  注册表键时间、FailureActions 字节、SCM 全量）。而它对用户零感知、根因在火绒内部。
  按 P16，在「7031 全文 + 恢复配置」拿到那一刻就该收口。
- 反方向（证明此判据不是一律放行）：系统自动重启**不能**收口 ——
  它会打断用户工作、有实际损失，且属本机可控项 → 必须回到 P10 继续验证。
- **零号信号被漏掉（atime/mtime 案例）**：用户说
  「都不是什么必须解决的问题……基本上纯粹只是我的好奇」之前，我还在准备
  「要不要提权改 `disablelastaccess` 做最小判别实验」的下一步方案。
  用户已经把决策代价降为零、并把交付目标从「答案」改成「成长」，**我没识别出来**，
  是被点破才结案。→ 这条补进判据，就是为了下次由我提出、而不是等用户来收场。
  - ⚠ **归因已于 19:11 收回**：我一度把它记成「G9 违规 / 读了没遵守 / 规则在 context 里
    没被应用的第 2 个独立样本」。**错。** transcript 时序：18:47:59 用户点破 →
    18:48:57 本会话第一次 Read `conduct.md` → 18:49:44 第一次 Read `closure.md`。
    点破前本会话读这两份文件 = **0 次**（11-03 那批 `conduct.md` 调用全是 Edit）。
    ⇒ 是**「预期内的没读到」**（当时无「应该读」的触发点），既不是「读了没遵守」，
    也不是「应该读但没读到」⇒ **不算踩坑**；我 19:11 记的「重复踩」也已收回。
    而且用 19:02 才写下的零号信号去定 18:47 的违规，属 F9 时序错配。
    ⇒ `conduct.md`「待验证」第 2 条**仍未产生有效样本**。
    ⇒ 但「沉淀过程中自我触发的一串错」是**真实偏差**，不因上游免罪而消失：
    过度定性 / 追溯定罪 / 把被测 case 写进规则（污染验证）/ 连锁作废动作。
    分类先于定性，见 `pitfalls/13-用户纠正的层级.md`。

**不适用于**：涉及不可逆操作、安全/隐私、对外发布、用户明确要求 root cause、
或结论会被他人当作事实依据去改配置时，一律**不许**用高度盖然性收口。
另：低代价不等于可以跳过分级标注，仍要写明「这是推定」。

**谁在用**：`排查方法论 skill`（验证净收益 / 边际收益）、
`evidence-discipline`（结案检查）、`qa-evidence-and-artifacts`（缺陷是否必修）。

## P17 形态变化即换题

**一句话**：排查开始前先把「要复现的现象」写成**可判别的操作性定义**
（显示形态 / 父子关系 / 同批数量 / 存活时长 / 触发方式）。
一旦被观测对象的形态改变，旧样本既不能验证也不能证伪旧命题 ——
**旧题结案；若再出问题，按新问题重新立题取证**，不沿用旧结论和旧复现判据。

**判别问句**：现在这个，和我一开始定义的那个，是同一个现象吗？逐项对定义里的每个字段。

**已知反例**：

- 本会话：07:48 那批的定义是「显示名 COM Surrogate / 挂在 BC、百度网盘等具体应用名下 +
  同批 9 个 + 挂约 12 小时不退」；一觉醒来变成「显示名全为 dllhost + 各自独立行 +
  右键菜单用完即退」。**显示名、分组、存活时长三项全变**。
  → 拿现在「没复现」去否定用户历史观察是错的；拿现在这批去解释旧显示名也是错的。
- 另一次（某游戏项目启动初期低帧）：我写「这次新出现启动初期卡」，用户澄清
  「以前也有掉帧，差异是恢复时间变长」→ F3 收回。现象定义没固定，把**程度变化**说成了**新增现象**。

**不适用于**：差异只是**程度 / 频率**，且操作性定义里已把这些列为可变量时，仍是同一题。
本会话正例：用户把「必现」改成「频繁」，我没有换题，而是用 `pinned_detect.py`
把频率量化成命中率，保持多轮同口径可比。

**谁在用**：`排查方法论 skill`（假设台账里的现象定义）、
`qa-evidence-and-artifacts`（复现判据）、`test-strategy-design`（回归判据）。

## P18 阳性对照只验方法，覆盖范围要独立校验

**一句话**：G1 的阳性对照亮，只证明「这个查询方法能打出数据」，
**不证明「查询范围够」**。凡是要写「唯一 / 首次 / 分界点 / 从未发生 / 没有别的了」
这类**存在性结论**，必须单独声明并校验三层覆盖：查询窗口、数据源保留起止、过滤条件。

**判别问句**：我这个「没有别的了」，是查全了没有，还是只查了我设的那一小段？
这个数据源最早能回溯到什么时候？那个时间点比我要断言的「分界点」更早吗？

**已知反例**：

- 本会话：我按「近 4 天」查 7031，阳性对照亮（4 条），于是断言
  「11/03 22:31:20 是唯一的服务安装 / 行为变化分界点」。
  实际 System 日志保留到 **某次**，完整历史里同形态 7045/7040 有 **18 对 / 35 条**、
  7031 最早 **10-17**。**窗口设窄了，对照再亮也救不了 → 整条结论被推翻并显式收回。**
- 第二次独立命中（历史）：只读到 `max_soc=100` 没读 `min_soc=2` → 误判用户没做满循环；
  以及只读到「发热不严重」没读「我现在也没有手机壳」。都是同一类**覆盖缺口**。
- 正面案例（本会话）：7036 在全量 1505 条 SCM 事件里 **0 条** → 先查了全量 ID 分布，
  判定该机根本不记录服务状态转换，于是把「日志里没有重启记录」标为**数据源不覆盖**，
  没有当成「没重启」。这是先校验覆盖才躲开的坑。

**不适用于**：只做局部快照、且不打算写存在性 / 唯一性结论时
（例如「此刻 dllhost = 2」），无需校验全历史 —— 但必须写明「仅此刻快照」，
不得从快照外推出「一直都是」。

**谁在用**：`evidence-discipline`（G1 补充 + 开工清单）、
`qa-evidence-and-artifacts`（日志保留期声明）、`排查方法论 skill`（负结果的判别力）。
