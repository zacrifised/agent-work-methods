# 低频字复核（server 模型唯一的系统性弱点）
## 现象
模型把生僻字替换成常见形近字。实测：
`呴 → 响`、`俎 → 姐`、`恻 → 侧`、`庖 → 厄`、`丐 → 巧`、`濡 → 需`。
18 处错误里 **6 处是"低频 → 高频"替换**。
## 这不是分辨率问题
把混淆对在 12–64px 各字号渲染比对，相似度**恒定**（呴/响 0.54–0.68），不随字号变化。
**混的不是像素，是频率先验。** 所以不能靠放大解决。
判定脚本：`scripts/legibility.py`（混淆对 × 字号扫描），
用于回答"这到底是分辨率问题还是先验问题"。
## 解法：不带频率先验的字形复核
`scripts/glyph_check.py`：对可疑位置的字格，把候选字用同一字体渲染成位图，
与真实像素做 NCC 比对。**关键是必须用同行已知字做对照组校准**——
真字会落在上限区间内，伪字明显在外。
```
实测（simsun，截图就是宋体）：
  对照组上限  无 0.669 / 鱼 0.668 / 以 0.701 / 湿 0.568   → 区间 0.568-0.701
  呴 0.573  ← 落在区间内
  晌 0.431 / 响 0.352 / 句 0.288 / 向 0.243  ← 都在区间外
```
## 三个坑（都实测踩过，会直接毁掉结论）
1. **字格定位必须用墨迹投影，不要用等距网格。**
   等距网格的累积漂移会让候选排名全是噪声；墨迹投影定出的字格稳定可用。
   `--seg` 会打印字格，相邻字因笔画相连可能合并在一格，需按宽度再拆一层。
2. **字体要先选定再固定，不能"多字体取最大值"。**
   取最大值会同时抬高所有分数、压缩区分度
   （响 从 0.352 抬到 0.555，呴 只从 0.573 抬到 0.560，差距从 0.22 塌到 0.005）。
   正确做法：**用对照组给每个字体打分，按【最差】那个控制字排序**
   （不是平均——平均会被个别字拉高，实测按平均会错选成黑体），
   选中后全篇只用这一个字体。
3. **结论是否随字体翻转，必须看得见。**
   脚本会打印每个字体的候选排名。各字体结论一致 → 证据强；
   翻转 → 证据弱，此时不要下结论。
   （本例：呴 在 simsun / simhei / STSONG 三个字体都排第一，
   只有明显不匹配的楷体除外——而楷体的最差控制字只有 0.139，一眼可辨。）
