# 测试设计方法选择参考

这个文件只在需求较复杂、需要解释覆盖依据，或用户要求测试点分析 / 草案用例矩阵时读取。

## 常见方法

### 等价类划分

适合：
- 输入项存在有效值和无效值分类
- 参数格式、类型、必填、权限或默认值有明确差异

常见覆盖：
- 有效类、无效类、空值 / 默认值、格式错误、权限错误

### 边界值分析

适合：
- 长度、数量、金额、时间、日期、阈值、枚举数量、图片比例或文件大小有明确上下限

常见覆盖：
- `min-1`、`min`、`min+1`
- 典型值
- `max-1`、`max`、`max+1`
- 若允许空，空值单独列

### 判定表

适合：
- 多条件组合
- 开关、身份、权限、状态、配置之间有明确结果映射

常见覆盖：
- 条件组合中的高风险交叉项
- 互斥条件
- 默认分支
- 不允许同时成立的组合

### 状态迁移

适合：
- 对象生命周期明确
- 不同状态下同一操作结果不同
- 存在阶段、轮次、审批、上下架、发布、撤回、终态

常见覆盖：
- 合法跳转
- 非法跳转
- 重复跳转
- 回退 / 恢复
- 终态后继续操作

### 场景法

适合：
- 用户端到端操作流程
- 涉及多个页面、多个服务、多个角色或多个端

常见覆盖：
- 主路径
- 分支路径
- 失败后恢复
- 跨端 / 下游消费一致性

### 正交试验

适合：
- 参数很多
- 全组合成本过高
- 需要在有限成本下覆盖主要组合风险

使用要求：
- 明确因素和水平
- 标出哪些高风险组合需要额外补点
- 不用正交结果替代已知高风险边界

## 组合建议

- 表单类需求：等价类 + 边界值
- 规则类需求：判定表 + 等价类
- 流程类需求：场景法 + 状态迁移
- 多角色 / 多端需求：场景法 + 判定表 + 对象绑定检查
- 高组合需求：正交试验 + 风险补点
- bug 补洞：错误推断 + 历史缺口归因 + 回归分层

## 使用规则

- 不是方法越多越好；方法必须匹配需求特征。
- 正式展开 case 前，先列测试点清单，再映射到 case 或 case 组。
- P0 / P1 case 必须能说明业务价值，至少追溯到放行风险、核心链路、历史缺口、用户损害或关键业务规则之一。
- 新需求 / 新功能不能因为目标对象自身代码路径存在就改用白盒预期；目标对象自身代码只能在 bug 补洞或已实现功能回归中辅助识别风险。用户明确指定的相似旧项目 / 旧仓库 / 旧玩法 / 旧后台可作为弱参考，用来补继承流程和历史风险，但不能替代当前需求真源。
