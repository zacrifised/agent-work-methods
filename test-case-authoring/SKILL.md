# 测试用例资产编写

## 范围

覆盖：从需求真源产出 / 修订测试用例资产（case、测试点、用例矩阵、覆盖矩阵、派生数据文件）。
不覆盖：用例评审与风险裁剪、测试执行、自动化脚本实现、产品代码修改、下游可执行断言拆解与 runner 路由。
「生成后自检门禁」是本 skill 内部的产出校验动作，不等于用例评审，不改变上述边界。

## 完成判据

- 输入包齐备：需求真源、设计与对齐材料、讨论补充材料齐；缺任一关键输入不进入正式编写，只输出缺失项 / 可确认项 / 假设项 / 最小澄清问题
- 任务类型（从 0 建 / 增补 / 重构 / 补洞）与影响粒度（单条 / 多条 / 跨端 / 回归分层 / 版本物料）已判定
- 关键图示 / 富文本材料已有输入清单、文本提取、视觉证据、事实映射；冲突已澄清
- 显式功能覆盖索引每行含来源锚点 / 需求事实 / 覆盖目标 / 覆盖证据 / 状态；状态仅 `covered` / `out_of_scope` / `pending_clarification` / `gap`，`gap` 不静默通过
- 预期只来自需求真源、设计材料或已确认澄清；不由待测实现反推
- 边界成对：该有时必须有、该没有时必须没有、其他作用域不得出现、切换后不得残留
- 一致性闭环覆盖提交值 / 接口响应 / 持久化或可查询值 / 刷新回显 / 下游消费 / 可复算来源
- 变体矩阵逐行写明生产端数据、回显值、消费端预期、不覆盖原因；不用一个样本代表全部
- 状态生命周期覆盖进入 / 停留 / 退出 / 下一阶段重置 / 终局 / 取消失败重试重连后的残留
- 正式改写按 Markdown 真源 → 派生数据 → 覆盖矩阵 → 交付说明 → 生成后自检 → 版本号 的顺序
- 贴 `scripts/check_assets.py` 的 `EVIDENCE_JSON` 原文，由独立执行方按 `observations` 复算；`ok` / 退出码只作辅助；改 skill 后跑 `--selftest`。
  **正式资产**用 `--dir <资产目录>`（含 YAML 派生双向一致）；**轻量模式**（仅测试点 / 草案矩阵、纯 Markdown 套件）用 `--dir <资产目录> --light`，不做 YAML 派生校验
- 生成后自检有活跃 finding 时先抛给用户裁决，不静默继续

## WHEN → THEN

**WHEN**：要写 / 改 / 补测试用例资产。
**THEN**：
1. 输入与前置检查：判任务类型与影响粒度；缺关键输入只输出澄清清单；图示材料先做提取与视觉复核；生成显式功能覆盖索引；正式编写前隔离工作区。
2. 判改哪类资产：先补验证点 → 再改旧 case → 最后新增 case；同步判是否波及跨端候选断言、覆盖矩阵、交付说明、版本号。
3. 对齐：轻量模式只做测试点 / 草案矩阵；命中 MAJOR / 多模块 / 多端 / 多角色 / 状态机 / 风险不可控时先给流程梳理供确认；正式编写前输出一次「规则调用检查点」（启用规则 / 证据来源 / 落到哪条 case / 不适用规则及原因）。
4. 正式改写：按固定顺序落盘，逐层同步；跑 `check_assets.py`。
5. 生成后自检：无活跃 finding 记录「无需关注项」；有则逐条汇总标题 / 严重度 / 影响 / 修复方向，等裁决后重跑校验。
6. Done Check：逐条核完成判据；进度提示至少让用户知道在第几步。

## 硬规则

1. QA 黑盒优先：从客户可感知结果、业务风险和验收证据出发；源码 / 变量名 / handler / 实现分支只作诊断线索，不作预期或通过条件。
2. 输入先行：不明确就澄清或标待确认，不擅自补写、改写或替产品定口径。
3. 显式覆盖：PRD 明确项逐项可反查；模块级覆盖不等于完成。
4. 边界成对、一致性闭环、变体矩阵、状态生命周期四条不得省略。
5. Markdown 是人工真源、派生数据是产物；双向一致，`gap` 不静默通过。
6. 多角色、多端、多阶段明确写出观察主体；步骤与预期一一对应。
7. 技术验证点写成明确值或明确判断方式；数据一致性 case 写清如何复算或对账。
8. 显式写假设项与不覆盖项；P0/P1 要能解释业务价值，不因「看起来重要」标高。
9. 标题低理解成本、用户可观察结果导向；case 对 PM / 开发 / QA / agent 都可读。
10. 输入仍不足时明确标「待补输入后继续」，不假装完成。
11. 通用且跨需求稳定成立的纠偏才升级为 skill 规则；一次性场景只进本次假设项。
12. 完成前验证贴原始输出；不采信断言自报 PASS。
13. 产出方不宣布放行；放行由独立执行方按原始观测量复算决定。

## 反例

- ❌ 用待测实现反推预期，或把源码分支写成通过条件。
- ❌ 关键 PRD / 图示缺失就开写，或擅自替产品定口径。
- ❌ 模块级覆盖就宣布完成；`gap` 静默通过。
- ❌ 边界只写「有」不写「没有」，不写其他作用域与切换后残留。
- ❌ 用单个样本代表类型 / 状态 / 平台 / 入口 / 消费端变体。
- ❌ 先改派生产物再改 Markdown 真源，或漏同步覆盖矩阵与交付说明。
- ❌ 自检有活跃 finding 却静默继续。
- ❌ 把一次性场景的纠偏升级成通用规则。
- ❌ 进度完全无感知，或 Done Check 只勾「已完成」不贴证据。
