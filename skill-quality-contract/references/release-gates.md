# 放行门禁

## 适用范围

- **G1–G9 仅适用于本 skill 自身的交接工具链自检**：核的是材料包生成、门禁脚本、
  故障套件的可靠性，**不以被评 skill 的文件为输入**。逐项核 G1–G9 只能回答
  「交接链路是否可信」，**不能回答「被评 skill 好不好」**。
- **被评 skill 的放行另按下方「S1–S5 判据清单」**，该组以被评 skill 的文件为输入。
  两组不互相替代；放行由 S1–S5 全过且 G1–G9 无阻断共同决定。
- 材料包第 2 节须同时列出两组，不得把 G1–G9 单独标为「放行门禁」。

## 被评 skill 判据清单 S1–S5（放行判据只看这一组，G1–G9 仅作阻断）

| # | 判据 | 操作定义（什么算过） | 可观测判据 |
| --- | --- | --- | --- |
| S1 | 平台契约 | **C12 仅扫 SKILL.md，不替代 S2 的逐文件扫描**；对**每个**被评 skill 目录跑 `python <contract-validator> <skill-dir>`；再跑官方 `quick_validate.py <skill-dir>` | 契约 14 项逐项 PASS；官方输出 `Skill is valid!`；两脚本完整绝对路径见材料包第 2 节 |
| S2 | 本体纯度 | **适用范围 = SKILL.md 本体 + 执行类 references**；逐文件 Grep 下方 S2 词表，命中的「执行判定依据 / 台账字段」按例外放行。**先验素材类文档**（案例库 / 参照实例）由审核方按文件名判定豁免，产出方不预写豁免清单；其中的「实测值 / 先验含义 / 表象陷阱」属数据字段，不按叙述类判 FAIL | 适用范围内叙述类命中 = 0；例外项与豁免项逐条给行号与判断；语义候选留痕条数 = `semantic_count`（或逐条说明豁免） |
| S3 | 检测层自验证 | **纯文档 skill 无自检脚本时改核 `scripts/fault_injection_suite.py` 的注入对照，并写明适用/豁免**；对每个自检脚本跑 `--selftest`；在临时副本注入 4 类故障：删项 / 词表或检查项表改空 / 扫描器源码改空 / 退出码短路恒 0；另核「单个 case 的 ok 写死恒真」这一自指极限形态 | 前 3 类注入后 `exit != 0` 或证据层翻红；退出码短路形态按 `EVIDENCE_JSON` 的 `coverage_ok` 与 `failed` / `gates_false` 原始列表复算为不通过（记通道异常，不采信 rc）；自指极限形态**由独立执行方按逐项返回与 `observations` 复算覆盖**，不要求脚本翻红。逐类注入命令、stdout 与 `EVIDENCE_JSON` 原文见动态取证文件 |
| S4 | 判定权外移 | 核完成判据是否要求按原始观测量复算，且不采信脚本 `ok` / 逐项打印 / 退出码作放行依据 | 逐条给一手证据；不存在「退出码 0 即完成」的判据 |
| S5 | 口径一致 | 核**包内实存的**主文件 / references / 模板（有 scripts 时含脚本）对「何时用 / 完成判据 / 不宣布放行」一致，且无失效节号引用 | 不一致 = 0；失效引用 = 0 |

**S2 词表**：`理由：` / `因为` / `为什么` / 来源 URL / `20xx-xx-xx` / `沿革` / `教训` /
`实测`。**语义类**（教学性对比 / 其他 skill 名）不作字面词表项，由审核方独立判读，不计入机械命中。
**例外**：执行判定依据（判据表里的字段名）、台账待填字段（如「降级理由写进验证报告」）
不算叙述残留；引用例外由**审核方**逐条给完整路径 + 行号 + 原文片段 + 一句人话判断，产出方不预写。

**S2 命中的裁定权在审核方**：产出方不在判据真源预写逐条裁定结论。
`scripts/scan_s2_exceptions.py` 输出字面词表命中与语义类候选的路径 / 行号 / 原文片段（均不含裁定）；
语义类由审核方独立判读并逐条给出完整路径 + 行号 + 原文片段 + 一句人话判断。
**留痕可核**：审核方须对 `semantic_hits` 逐条留痕，留痕条数 = `semantic_count`，
或逐条说明为何不需裁定；判据真源不预写裁定结论。

## 判定规则

移除内嵌的 22 行跨对象裁定表
（裁定权回归审核方）；S2 语义类改为审核方独立判读、不计字面词表，并要求对 `semantic_hits` 逐条留痕；G5 补 §4 自检的实跑断言；
工具链索引补 `scripts/scan_s2_exceptions.py`。变更范围仅限本节与上述判据行，不改动 G1–G9 的二值语义。

- **全过才放行**：S1–S5 全部 PASS 且 G1–G9 无 FAIL = 可放行；任一项 FAIL = 不放行。
- **不设分数阈值**：评分只作趋势、增量对比与发现盲点。
- **元层覆盖断言**：`verify_gates.py` 的结果必须恰好 9 项且 G1–G9 标识齐全，缺项 `exit 2`。
- **结构化证据**：`verify_gates.py` 输出一行 `EVIDENCE_JSON`（`observations` 逐 G 原始观测量、
  `gates` 派生 ok、`coverage_ok`、`inconsistent`、`failed`、`gates_false`、`expected_exit`）。
  独立执行方先用 `observations` 自行导出各 G 的 PASS/FAIL，再与 `gates` 比对；
  不采信 `gates[].ok`、逐项 PASS 字样或退出码。`inconsistent` 非空即异常。
  证据与 stdout 的 FAIL 项矛盾时，按更严格一侧判定，并记「证据通道异常」。
- **每项必须能被故障推翻**：`scripts/fault_injection_suite.py` 只把每个已知故障注入临时副本，
  输出该次运行的 `returncode`、证据摘要与原始 FAIL 项。推不翻的项改到能翻，或移出门禁表。
- 改本 skill 任一文件后跑 `python scripts/verify_gates.py`，全过才交付。
  逐项结论由独立复核判据得出。
