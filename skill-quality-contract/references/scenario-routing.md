# 场景契约

## 1. 工作相关判定（主 agent 侧）

| 类别 | 定义 | 处置 |
| --- | --- | --- |
| **工作相关** | 用于职业 / 项目 / 交付 / 流程 / 质量活动的 skill（测试、QA、测开、文档产出、排查、自动化、归档、评审等） | **必须走本规范做专家评审** |
| **非工作** | 个人兴趣 / 生活 / 娱乐 / 一次性工具 | 不强制，做参考 |

**边界不确定 → 默认按工作相关（从严）**。

**可观测正向判据**：新 skill 的 `SKILL.md` frontmatter 中 `category` 属
`methodology` / `qa` / `testing` / `engineering` / `delivery` 之一，
**或**该 skill 被任一 workspace 文档引用 → 判工作相关。
产出方须在材料包或落盘清单记一行「工作相关判定 = X，依据 = <字段值 / 引用位置>」。

该判定由主 agent 提出、用户确认；会话调用本 skill 即表示判定已完成，本 skill 不重判。

## 2. 场景边界

| 不覆盖 | 走哪里 |
| --- | --- |
| 用产出的 skill 生成下游产物（test case、排查结论、报告等） | 子 agent 独立审核，不走本流程 |
| 非工作 skill | 参考本规范，不强制 |
| 判断「要不要评审」 | 调用前已完成 |
| 复评本 skill 自己 | 判据外部于被评对象 |
| 尚未落盘、磁盘上没有文件的方案 | 不在本场景内 |

## 3. 人工动作

- **召唤专家**：Expert 需用户手动召唤，助手无权加载或静默启用（机制见 `expert-mechanism.md`）。
- **提供无背景执行者环境**：产出方处于带记忆注入的会话内，无法自证「无背景」。

## 4. 裁决回流

1. 标 `external_unverified`：第二方结论是二级输入，只提取结构，不直接改成结论。
2. **只裁分歧**；一致项不额外论证，不写「双方一致」当支持证据；
   整轮收工仍须 S1–S5 全过且 G1–G9 无阻断。
3. 分歧逐条写证据裁决；需用户决策的项给**选项 + 建议及其依据 + 完整出处**。
4. 未召唤时如实写「已提醒召唤，专家审未执行」。
